# NodFirst 0.2.0 — lessons from the first real project (pre-release)

**Nothing gets built until you say yes.** NodFirst is a Spec-Driven Development kit in plain Markdown for any AI coding agent: you decide and approve, the agent writes, checks, reports and stops.

Documentation: **https://kaylit.github.io/nodfirst/**

## Why this version
NodFirst 0.1.0 was used for a whole feature of a real web app, Shortz: from `init` to an independent `verify` (three runs, another model) and deployment. Its documents are now in the repository as the first **real** example (`examples/shortz/`), and what the run showed is in this version.

## In this version
- **Close a feature knowingly.** After `verify` you either fix or close: `/nodfirst-verify close accept F3: <reason>`. Every serious problem left is named with a reason and a follow-up; the agent records your decision and never changes the verdict to fit it. `next` knows a closed feature.
- **Checks only you can do no longer block the verdict.** Things the agent cannot check from its environment (a phone, the CI console, the live site, a screen reader) go to "Needs a human" as checkboxes, never as passed. The three verdicts now have exact rules, and a re-run accounts for every previous finding.
- **Lessons in every project.** When you correct the agent, it proposes a line for `project/lessons.md`; when you close a feature, up to three. It writes only what you accept.
- **Honest maturity, updated.** What Shortz used for the first time (Solo profile, Git checkpoints, Cursor commands, `design`, `verify`, the `backend` module) is marked as used; the `web` module lists what is now proven.
- **A real example**, with notes on how it went and what it taught the kit.

## Update from 0.1.0
Replace `nodfirst/` and `AGENTS.md` in your project, keep `project/`, `specs/` and `docs/`, and type `/nodfirst-init update`. Your profile does not need changes.

## Maturity (please read)
Still an **early version**. Working profiles Guided and Team, `adopt`, `next`, `fix`, `clarify`, `design-system`, `specify` from your material, the `mobile` and `desktop` modules and the new closing step have not been used on a real project yet. The status of every part is in the README.

Full list of changes: `CHANGELOG.md`.
